# Lista de chequeo de revisión de código

Úsenla al terminar de programar una tarea y antes de crear la solicitud de fusión. Revisen el código completo para cada punto. Si un punto no se cumple, registren el defecto con su tipo, la fase inyectada Implementación y la fase removida Revisión de código.

## Funcionalidad

- [ ] El código hace lo que pide el diseño y cumple los criterios de aceptación del requisito.
- [ ] Los casos alternos están programados: datos vacíos, datos inválidos, elementos que no existen.
- [ ] Los cálculos dan el resultado esperado con al menos un ejemplo verificado a mano.

## Datos y variables

- [ ] Las variables se inicializan antes de usarse.
- [ ] Los nombres de variables, funciones y archivos siguen la convención del equipo.
- [ ] Los ciclos y los índices empiezan y terminan donde deben.

## Interfaz y mensajes

- [ ] Los datos que llegan del usuario se validan antes de usarse.
- [ ] Los mensajes de error indican qué pasó y qué puede hacer el usuario.
- [ ] Las llamadas entre componentes envían y reciben los datos en el formato acordado.

## Presentación del código

- [ ] El código está ordenado e indentado de forma uniforme.
- [ ] Las partes que no son evidentes tienen un comentario breve.
- [ ] No quedan líneas de prueba, código comentado sin uso ni datos de ejemplo que no correspondan.
