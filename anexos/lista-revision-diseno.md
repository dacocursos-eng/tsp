# Lista de chequeo de revisión de diseño

Úsenla al terminar el diseño de una tarea y antes de implementarla. Marquen cada punto al verificarlo. Si un punto no se cumple, registren el defecto con la fase inyectada Diseño y la fase removida Revisión de diseño.

## Cobertura del requisito

- [ ] El diseño cubre todos los criterios de aceptación del requisito.
- [ ] Cada pantalla, componente o dato del diseño corresponde a un criterio de aceptación o a una necesidad registrada.
- [ ] Están definidos los casos alternos: datos vacíos, datos inválidos, elementos que no existen.

## Pantallas e interacción

- [ ] Cada pantalla indica qué datos muestra, qué datos pide y qué acciones permite.
- [ ] Los mensajes al usuario están definidos: confirmaciones, errores y avisos.
- [ ] La navegación entre pantallas está definida: de dónde se llega y a dónde se va.

## Datos

- [ ] Cada dato tiene nombre, tipo y reglas de validación.
- [ ] Los datos que se guardan y los que se calculan están diferenciados.
- [ ] Los nombres son coherentes con los de los demás diseños del proyecto.

## Componentes

- [ ] Cada componente tiene una responsabilidad clara.
- [ ] Las entradas y salidas de cada componente están definidas.
- [ ] El diseño reutiliza los componentes que ya existen en el proyecto cuando aplica.
